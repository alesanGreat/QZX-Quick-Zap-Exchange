### Security, interoperability, and CI hardening

- Repair the cross-platform validation matrix, including macOS Unix-socket fixtures,
  build-backend prerequisites, isolated network fixtures, and Golden Core command
  count assertions.
- Remove the current dependency vulnerability set: upgrade PyJWT to 2.15.1,
  raise Go's `golang.org/x/sys` security floor, and pin the Java MCP reference to
  MCP SDK 2.0.1 with Jackson 3.1.7 and SLF4J 2.0.20.
- Harden Result Contract JSON evidence with explicit UTF-8 byte transport, one
  interoperable leading BOM, unpaired-surrogate rejection, and a deterministic
  QZX nesting limit across supported CPython versions.
- Refresh the official MCP Python and TypeScript reference integrations to SDK
  2.2.0 while preserving MCP 2026-07-28 evidence, hash-locked Python dependencies,
  and dynamically verified TypeScript package provenance.
- Refresh pinned GitHub Actions for Node, Java, CodeQL SARIF upload, and the
  FreeBSD/OpenBSD/OmniOS/Solaris VM runners while retaining immutable commit-SHA
  pins.
- Preserve the existing 89-command public QZX surface and keep release/package
  compatibility claims aligned with the evidence actually generated by CI.

## 0.2.2.0.12 — 2026-09-25

<!-- qzx-release-summary-en:

<!-- qzx-release-summary-es:

### Smaller command units with the same public surface

- Split large file, network, and system command implementations into focused
  internal workflow modules while preserving their documented command names and
  result contracts.
- Complete the content-first `detectFileType` extraction and keep its bounded
  sampling, optional libmagic refinement, and extension evidence covered by the
  existing regression suite.
- Regenerate the canonical command reference from runtime metadata so source and
  documentation describe the same 89-command inventory.

### Safer permission and Windows test boundaries

- Refuse `changePermissions` modes that would remove the owner's required
  read/write access or directory traversal instead of allowing QZX to lock its
  own caller out.
- Replace permission-denial fixtures that mutate real ACLs or revoke runner
  access with injected failure boundaries.
- Use inherited Windows temporary-directory permissions, normalize the long
  temporary path, and clear Git-created read-only file attributes only during
  teardown so temporary repositories clean up reliably without restrictive ACLs.

## 0.2.2.0.11 — 2026-09-25

<!-- qzx-release-summary-en:

<!-- qzx-release-summary-es:

### Auditable human-use evidence without behavioral surveillance

- Aggregate command executions locally by UTC day and emit at most one closed,
  globally aligned 10-day `usage_window` when QZX next runs.
- Keep only canonical command names, invocation counts, accumulated/max command
  duration and coarse TTY/foreground/recent-input counters; never send arguments,
  terminal input/output, paths, file content, key values, pointer coordinates,
  trajectories, clicks or raw HID events.
- Add bounded cross-process locking so concurrent agents do not silently lose
  local usage counts; if the lock is busy, QZX skips telemetry rather than
  delaying the command.
- Add Human Evidence Score v1 in the private admin with explicit dimensions for
  external origin, interactivity, coarse presence, persistence, version
  continuity and reserved independent verification. Recurrence alone cannot
  promote an installation to a human tier.
- Add the latest closed-window Top 10 commands by use and by average duration,
  including maximum duration and sample count so isolated spikes remain visible.
- Extend the canonical `qzx-adoption-status.cmd` contract to surface the same
  human-evidence and command-usage aggregates without credentials or manual SQL.
- Preserve existing `version_first_run` ingestion for older clients and keep
  telemetry failure fully non-fatal.

## 0.2.2.0.10 — 2026-09-24

### Faster project language analysis without sacrificing universal installs

- Use Tokei 15 through a Rust/PyO3 `cp311-abi3` backend for `projectLanguages`
  when a native wheel is available, replacing the former Pygments-heavy hot path
  while preserving exact QZX accounting and the existing Python fallback.
- Build native wheels for Windows x64, Linux x64, macOS Intel and Apple Silicon,
  while continuing to publish the universal `py3-none-any` wheel and source
  distribution so users are never required to install Rust.
- Support batch/one-pass analysis for composition reports and keep the local
  development native cache outside Dropbox, fingerprinted by the Rust sources.
- Preserve parity between native and reference scans for files, bytes and line
  counts; the measured workspace composition path dropped from roughly 50.7
  seconds before the optimization to about 1.9 seconds in final validation.

### Faithful, bounded file reading and creator discovery (development only)

- Replace `readFile`'s unbounded whole-file default with a 64 KiB source-byte
  page, optional line limits, strict BOM-aware Unicode and explicit legacy
  encodings. Undecodable text fails instead of returning corrupted success.
